# Make key information dominant

Decide what the user should see first and do next. Spend the most space on these. Make them big, bold, and readable.

- Design the layout around the main canvas, key results, charts, and primary controls before adding labels or subheadings.
- Cut titles, intros, section headings, group-box titles, and card labels that merely name the obvious thing next to them. Do not give each widget or component its own heading, subtitle, and caption. In web UIs, never spend a full-width vertical banner just on a title or logo; fold identity into the toolbar or sidebar.
- Do not label self-explanatory elements. Use short terms or phrases where sufficient, and reserve extended prose for non-obvious caveats that materially change interpretation (e.g. "This data has not been reviewed, so may be incorrect"), placed beside the affected result.
- Put auxiliary information such as units beside the corresponding value, and a control beside the result it changes. Do not add extra linebreaks or paragraphs for items that logically live on one line.
- Reserve extended prose for where details are not obvious to the user, e.g. "This data has not been reviewed, so may be incorrect", "This includes <subcategory>, see <link> for <specific case>". Keep caveats that materially change the interpretation beside the affected result.
- Expose a useful control for every primary task by default.
- If color can be used to meaningfully represent things such as categories, high / low values, do so and do so consistency across the interface.
