# Make key information dominant

Decide what the user or reader should see first and what they should be able to do next. Spend the strongest type, colour, and space on those two things. Put them in the first view.

- Cut the title, intro, section heading, group box title, or card label if it merely names the obvious thing next to it. Do not give each widget or component its own heading, subtitle, and caption.
- Put a unit beside its value and a control beside the result it changes. Label a shared scale or series once. Never make a user reconstruct one thought from fragments scattered across the window or page.
- Give the main canvas, number, chart, or finding room before fitting in explanation or secondary chrome. Do not keep secondary copy by shrinking it into a cloud of small text.
- Expose a useful control for every primary task by default. Put refinements, methods, and exact chart details behind expansion, focus, or hover. Keep caveats that materially change the interpretation beside the affected result.
- Check the first view at its actual size. Name what the eye lands on and try the most common action. If the chrome wins or the action starts with opening a panel, cut or move something before handing it over.

For example, lead with two large comparison charts. Put the comparison choices above the chart they control, write the annual unit beside each total, and use a single shared legend.
